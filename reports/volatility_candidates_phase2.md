## Methodology notes

- **Threshold**: 5% over 24h -- lowered from phase 1's 10% specifically to reach a ~70-incident target for phase 2's larger scaling goal (45->150 total incidents). This means phase 2's volatility incidents are, on average, smaller and calmer moves than both the original 12 (hand-picked famous crashes) and phase 1's 18 (10%+ automated). Flagged explicitly since this affects the deterministic baseline's reserve_skew-threshold behavior in a known, already-documented way (see reports/loocv_45_incidents.md's finding that calmer volatility incidents cross the deterministic rule's manipulation threshold far less often).
- **No lookahead**: heartbeat_elapsed is read at block-1, matching this project's fixed anchoring-artifact convention.
- **Cleanliness gate**: unchanged from phase 1 -- 5% cross-venue agreement, heartbeat_elapsed <= 1800s.
- **Block resolution**: uses a timestamp-linear estimate + short local binary search (not a blind full-range binary search), needed to keep ~70+ block lookups tractable -- a blind approach cost the malfunction-search pass over an hour for a similar volume.
- Every value in the table above is a live on-chain or exchange-API read for this run, not estimated or interpolated.
